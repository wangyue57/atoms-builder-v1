# 维护开发与文档更新规则

日常工作从 [AGENTS](../AGENTS.md) 和 [代码地图](CODEBASE-MAP.md) 开始。默认在现有基线上完成用户的优化、修复和新增需求，不重走旧建站批次。

## 任务与实现

1. 在 [维护任务板](TASK-BOARD.md) 记录任务 ID、Owner、依赖、Allowed/Forbidden paths、验收方式。局部任务可由一个 Agent 完成，独立子任务才并行分派。
2. 阅读待修改源码和相关测试；行为/架构改动先核对 [ARCHITECTURE](ARCHITECTURE.md)。跨模块结构以 [INTERFACES](INTERFACES.md) 和正式 Contracts 为准。
3. 每个 Agent 只改授权路径；公共 Contracts、历史迁移和跨模块集成由 Lead 协调。发现范围不足时先记录影响，不能在调用方偷偷绕过 Interface。
4. 新 Adapter 先做确定性验证，再验收真实运行路径。明确“实现存在”“已装配”“用户可用”分别证明到了哪一步。
5. 涉及长期架构取舍时新增/替代 ADR；普通功能不必新建完整设计文档，在任务和当前架构相关章节说明即可。不要更新归档的零到一设计。

## 按改动影响验证

- 模块实现：相关包测试与编译；公共 Interface：加 Contract Tests；跨模块调用：加集成验证。
- 网页交互：本地 API 测试，必要时做 Chrome 交互验收。fixture 验收不等于真实模型或产品 Reviewer 浏览器验收。
- 仅文档：核对源码事实、本地链接、移动后的引用和 `git diff --check`，不重跑产品测试。
- 模型、环境和测试错误分别记录；不能放宽断言来掩盖问题。真实付费验证与离线测试区分记录，不暴露凭证。
- 完成报告包含改动文件、任务 ID、命令及结果、迁移/Interface 影响、风险和后续依赖。

## 文档职责与更新矩阵

文档随代码在同一任务交付。实现 Owner 提供证据，Lead 汇总共享文档，避免并行覆盖。

| 改动 | 更新位置 | 维护范围 |
|---|---|---|
| 任意任务结束、失败或范围调整 | [TASK-BOARD](TASK-BOARD.md) | 当前任务状态、验收结果和阻塞。近期完成任务可留在板上，累积后归档 |
| 用户能力、缺口、限制变化 | [STATUS](STATUS.md) | 当前事实和原目标差距；不要重复任务流水账 |
| 模块入口、文件位置或调用链变化 | [CODEBASE-MAP](CODEBASE-MAP.md) | 源码入口、职责、需求导航和相关测试 |
| 启动、依赖、环境变量、端口变化 | [LOCAL-DEVELOPMENT](LOCAL-DEVELOPMENT.md)，必要时 [README](../README.md) | 可执行步骤和限制，不写密钥值 |
| 公共类型/事件/Interface 变化 | [INTERFACES](INTERFACES.md) 与 Contracts 测试 | 版本、不变量、兼容影响；不重复整份 Schema |
| 架构或维护约束变化 | [ARCHITECTURE](ARCHITECTURE.md)，长期决策写 [ADR](adr/) | 当前结构与必须保持的约束，不把未来方案写成已落地 |
| 执行验证或上线验收 | [INTEGRATION-STATUS](INTEGRATION-STATUS.md) | 日期、任务、命令、结果和验证范围；未运行的检查明确标记 |
| 阅读/协作/文档分类规则变化 | [AGENTS](../AGENTS.md)、本文、[文档索引](README.md) | 让新会话能找到正确入口，避免每轮必读历史规划 |
| CVM 部署方案/实际操作变化 | [部署方案](DEPLOYMENT-SINGLE-CVM.md)、[部署入口](../deploy/README.md) | 部署前置条件、拓扑和可执行步骤；真实结果仍记入验收记录 |

不强制每次修改都更新 STATUS、代码地图或架构文档；只有对应事实变化才修改。文档-only 任务的检查证据可以直接留在任务板。不要为“看起来有更新”重复写入同一段状态。

## 保持轻量与可追溯

- 每类事实有明确归属，其他文档用链接引用；README 只保留启动和导航。
- 不手写易失效的源码行号、全量函数清单、依赖版本表或整份 Schema；链接代码并用稳定符号名定位。
- 模块复杂到代码地图无法清晰说明时，再在模块旁增加 README；普通小需求不新增独立文档。
- [历史建设资料](archive/bootstrap/) 只读，不继续更新批次和角色分工；已有错误可添加注明日期的勘误，不改写历史完成状态。
- ADR 的 Accepted 不是已实现证明。原始计划未完成能力留在 STATUS，只有用户选择推进时才进入活跃任务。
- 文档与源码冲突时核对实际源码/测试并修正文档，报告修正依据；不要用归档掩盖缺失功能。
