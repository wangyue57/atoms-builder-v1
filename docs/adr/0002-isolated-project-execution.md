# ADR 0002：在隔离沙箱中运行生成代码

状态：Accepted

## 背景

Builder 生成的代码、依赖和命令都不可信，不能在 Control API 或 Worker 主进程中运行。

## 决策

一期默认使用单腾讯云 CVM 上的 rootless 容器作为 `SelfHostedContainerAdapter`，并保留 Local Adapter 用于测试。所有生成代码、依赖安装、构建和预览都在沙箱中执行。E2B 作为可选的增强隔离 Adapter，不是一期部署前提。

## 原因

- 形成清晰的安全 seam。
- 让单 CVM 可以自包含部署和本地运行。
- 限制文件、进程、网络和资源。
- 可以独立销毁和恢复项目执行环境。
- 后续可以替换为 E2B、Firecracker、TKE 或其他更强隔离实现。

## 后果

- 单 CVM 的容器隔离弱于微虚拟机，不能直接视为面向陌生公网用户的强隔离平台。
- 需要管理沙箱生命周期、网络策略和日志上限。
- 本地测试必须通过同一 Workspace 接口模拟沙箱。
- 需要在用户规模增长前把 Sandbox 拆到独立实例或容器集群。
