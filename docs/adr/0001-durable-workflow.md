# ADR 0001：使用持久化工作流编排长时间运行的 Agent 任务

状态：Accepted

## 背景

一次项目构建可能包含模型调用、命令执行、浏览器测试、用户审批和部署。任意一步都可能超时、失败或需要等待用户。

## 决策

使用 Temporal 编排 Run。模型调用、沙箱命令、测试和部署都是 Activity；Workflow 只保存可序列化状态和流程控制。

## 原因

- 支持重试、超时、取消和等待审批。
- Worker 重启后可以恢复。
- 长任务不需要依赖 HTTP 请求生命周期。
- Activity 可以用幂等键保护外部副作用。

## 后果

- 团队需要维护 Workflow 和 Worker。
- Activity 必须设计为幂等。
- 完整源码和大对象不能写入 Workflow history，必须使用对象引用。
